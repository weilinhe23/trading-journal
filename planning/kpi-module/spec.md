# PTS KPI 跟踪模块

## 目标

建立独立的 `/kpi` 当日仪表盘。用户只录入系统当日的实际 PTS，页面立即展示本周、本月、本季度、本半年度和本年度的基准及乐观 KPI 完成情况。

## 核心规则

- 交易日期默认使用当前美东交易日，不提供周期页面或周期录入。
- 每日基准目标默认 `100 PTS`，每日乐观目标默认 `200 PTS`。
- 周期目标 = 周期内美股交易日数 × 对应每日目标。
- 美股交易日自动排除周末和 NYSE 常规休市日。
- 实际 PTS 只按日保存，周期累计由系统自动计算。
- 日期统一按美东交易日的 `YYYY-MM-DD` 处理。
- 半年度按自然半年划分：1–6 月为上半年，7–12 月为下半年。

## 页面

`/kpi` 使用单页仪表盘布局：

- 页头显示系统当日日期。
- 当日录入区只填写实际 PTS 和可选备注。
- 同时显示本日基准、乐观目标状态。
- 一张横向柱状图同时比较 5 个周期的基准和乐观完成率。
- 图表下方显示每个周期的累计实际值、目标值和准确完成率。
- 一张折线图展示实际 PTS 的逐日累计趋势。
- 折线图支持本周、本月、本季度、本半年度和本年度切换，默认本月。
- 累计趋势只画到当前美东交易日，未记录日保持上一交易日累计值。
- 保存或清除当日记录后，全部周期图表自动刷新。

Dashboard 只展示本周基准目标摘要和进入 `/kpi` 的链接。交易日志和周报不提供 KPI 输入入口。

## 完成率

```text
基准完成率 = 周期累计实际 PTS / 周期基准目标 PTS
乐观完成率 = 周期累计实际 PTS / 周期乐观目标 PTS
```

完成率允许超过 `100%`；进度条最多填满，图表和文字继续显示真实百分比。

## 数据模型

### KpiTargetSetting

保存每日目标变更历史：

- `effectiveFrom`：生效日期，唯一。
- `dailyBaseline`：每日基准目标。
- `dailyOptimistic`：每日乐观目标。

### KpiDailyRecord

保存唯一原始数据：

- `date`：交易日期，唯一。
- `actualPcts`：当日实际值，允许零和负数。
- `note`：可选备注。

KPI 数据不依赖 `DailySession`。在 KPI 页面录入数据不会创建交易日志。

## API

```text
GET/PUT        /api/kpi/settings
GET/PUT/DELETE /api/kpi/records/[date]
GET            /api/kpi/summary?period=week&date=YYYY-MM-DD
```

`period` 支持 `day`、`week`、`month`、`quarter`、`half`、`year`。

## 首版不做

- 手动录入周、月、季度、半年度或年度累计值。
- 历史日期导航和历史记录补录。
- 多种 KPI 指标或任意公式编辑器。
- 特殊临时休市日后台管理。
- 云端提醒、排名或游戏化功能。

## 验收标准

1. 打开 `/kpi` 时自动使用当前美东日期。
2. 用户可以保存、修改和清除系统当日实际 PTS。
3. 非美股交易日不能录入记录。
4. 保存当日记录后，5 个周期的累计值和图表同步更新。
5. 每个周期同时展示基准和乐观完成率。
6. 累计折线图可以切换 5 个时间维度，并正确累计零值和负值记录。
7. 半年度按当前日期自动选择上半年或下半年。
8. 所有周期目标按美股交易日和当日有效目标自动计算。
9. 零、负数和“未记录”可以正确区分。
